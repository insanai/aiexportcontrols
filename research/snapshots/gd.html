Guidedog

English | 简体中文 | 日本語 | 한국어 | हिन्दी | Español | Deutsch

Write once. Explain well. Publish on the web and on paper.

Guidedog builds a documentation website and a PDF book from the same reStructuredText or Markdown files. We keep one set of source files and publish it for readers on the web and on paper. The release provides one guidedog executable, with PDF typesetting, diagram rendering, and music engraving included.

Sphinx inspires the authoring workflow. Guidedog is an independent system: configuration is declarative TOML, API extraction is static, and Python configuration and extensions are never executed. Complete Sphinx compatibility is not a goal.

Start a project

guidedog quickstart docs
guidedog build html docs
guidedog build pdf docs
guidedog serve docs

The project contains conf.toml, index.rst, _templates/ (layout.html, book.typ, discussion.typ, article.typ, and theme.typ), and _static/ (guidedog.css, guidedog.js, and typography.js). Templates and static assets are ordinary files that we can edit locally. HTML provides navigation, search, code highlighting, diagrams, equations, and Knuth-Plass paragraph typesetting. PDF books provide chapters, cross-references, figures, indexes, and language-aware typesetting. We can embed Graphviz or Typst drawing source, including CeTZ and Fletcher, directly in RST and MyST with automatic HTML and PDF assets; see the diagrams chapter.

We embed LilyPond notation directly in RST and MyST with the native lilypond directive, including staves, up to four simultaneous voices per staff, lyrics, guitar tablature, structured \markup, and common markings; see the music chapter and the songbook task. Outlined Bravura SVG and PNG figures work in HTML and multi-system PDF books without an installed LilyPond program:

.. lilypond::
   :caption: Beethoven's Joy theme, four bars in C major.
   :alt: A four-bar melody beginning E, F, G and ending with dotted-quarter E, eighth-note D and half-note D.

   \fixed c' {
     \clef treble
     \key c \major
     \time 4/4
     e2 f4 g | g4 f e d | c2 d4 e | e4. d8 d2 |
   }

The built-in theme follows the system theme by default, with light and dark choices; Guidedog's own documentation website defaults to the light reading edition. The website detects the browser language on its landing page and repository overview. A saved choice takes precedence; direct links to an edition or chapter remain explicit requests.

guidedog convert notes.md --to pdf --output notes.pdf
guidedog clean docs
guidedog migrate conf.py

API documentation is read from source without running it: Python (autodoc), Odin (odindoc), and Rust crates (the rust domain and the rust_autoapi_* settings).

Install

Each release has an archive for Linux (x86-64 and ARM64) and macOS (Apple silicon and Intel), plus a Windows x86-64 ZIP. Each archive contains the guidedog executable and its notices. GitHub Pages publishing, static site publishing, and discussions are linked plugins; gd-graphdog encapsulates Graphviz as a library. The Typst compiler and Bravura 1.482 music font are embedded, tree-sitter is compiled in, and Graphviz is linked statically, so nothing else needs to be installed. The Windows ZIP bundles Graphviz DLLs; we keep the whole extracted folder together. Linux needs glibc 2.35 or later; macOS needs version 12 or later. We download the archive for our system and SHA256SUMS, then check and install it:

sha256sum -c --ignore-missing SHA256SUMS      # on macOS: shasum -a 256 -c --ignore-missing SHA256SUMS
tar -xzf guidedog-linux-amd64.tar.gz
sudo install guidedog-linux-amd64/guidedog /usr/local/bin/

On macOS, install from the official Guidedog Homebrew tap. Homebrew selects the Apple silicon or Intel archive. The tap also supports Linux:

brew tap insanai/guidedog
brew install insanai/guidedog/guidedog
guidedog --version

The executable is not code-signed: on macOS, remove the quarantine from a browser download with xattr -d com.apple.quarantine guidedog. The release notes describe each platform's limits.

Build from source

Install Rust 1.99 or later (with rustup), a C compiler (tree-sitter's grammars are C), and the Graphviz development files: libgraphviz-dev on Debian and Ubuntu, graphviz-devel on Fedora, graphviz from Homebrew on macOS. (Or build Graphviz statically, as the releases do: cargo xtask graphviz, then build with GUIDEDOG_GRAPHVIZ_STATIC=target/graphviz/16.1.0; the programs then need no Graphviz at run time.) Then build the workspace:

cargo build --release -p guidedog-cmd
target/release/guidedog --version

The executable is in target/release. On macOS with Homebrew, point the linker at Graphviz first: export LIBRARY_PATH="$(brew --prefix graphviz)/lib". The Typst compiler is embedded by default (the embedded feature of gd-typst); without it, Guidedog runs an installed typst 0.15.1 for PDF books, while .. typst-diagram:: and .. lilypond:: with :format: png require the embedded compiler. On Linux, the embedded compiler's package downloader links a vendored OpenSSL, which needs perl and make to build.

Before sending a change, run what CI runs:

cargo fmt --all --check
cargo run -p check              # source limits: function and file length, line width
cargo xtask tables --check      # generated Unicode, entity and SMuFL tables
cargo xtask check-music-font    # pinned Bravura 1.482 font and metadata
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo xtask fetch-fonts --music && cargo run -p music-check

RELEASING.md describes the release workflow.

Translate with Guidedog

mkdir -p docs/manual/_editions
guidedog build -b gettext docs/manual docs/manual/locales/templates -W
guidedog intl update -p docs/manual/locales/templates \
    -l zh_CN -l ja -l ko -l hi -l es -l de docs/manual
guidedog intl stat -l zh_CN -l ja -l ko -l hi -l es -l de docs/manual
guidedog build -b html docs/manual docs/manual/_editions/de \
    -D language=de -D 'html_extra_path=[]' -W

Translate and review msgstr values in the PO files. Guidedog extracts POT files, merges catalogs, reports progress, and builds each edition. It does not invent translations. Commands, paths, code, API names, and reference targets stay unchanged. The website landing page, the manual, and the repository overview are translated; the API reference and GDS remain English. cargo xtask build-site assembles all editions, their PDF books, and the discussions into the website.

GitHub readers choose a README language using the links above. Automatic language selection belongs to the generated documentation website.

Publish to GitHub Pages

guidedog publish pages publishes through the built-in GitHub Pages plugin. It builds with Guidedog's own engine, guides us through missing setup, and publishes one complete site generation. guidedog pages exposes configuration, credentials, recovery and workflow generation. We install no separate publisher executable.

guidedog publish pages --repository=octo/manual --project=docs
guidedog pages status
guidedog pages workflow --write

For scripted setup we use guidedog pages init, auth import, bind, and setup. GitHub Actions can build and deploy after every push using the generated workflow. See Publish to GitHub Pages.

Build plugins transform source text, complete HTML pages, and static assets through a typed, versioned contract. A plugin is an ordinary Rust crate. We link it into our own guidedog with gd_cli::run_with, or we run it as a separate program that guidedog plugin register pins by SHA-256. A plugin can also add commands to guidedog itself, listed by guidedog --help. guidedog publish --timeout=SECONDS bounds each complete exchange with a publisher (default: 300 seconds); choose a value longer than --wait. After an unknown outcome, recover before publishing again.

Keep discussions

guidedog dsc keeps proposals and decisions as reStructuredText records, one file each, and builds them into a website and PDF books. Each catalog has a prefix: Guidedog's design records use gds, and another project might use eds.

guidedog dsc init docs/eds --prefix=eds --name="Enso Discussions"
cd docs/eds
guidedog dsc new "Cache policy" --labels=architecture
guidedog dsc promote cache-policy
guidedog dsc state 1 --to=accepted --reason="Review converged"
guidedog dsc build

A catalog's discussion.toml sets its lifecycle states, record types, and numbering, and guidedog dsc config prints it. The commands come from the discussion plugin, which every guidedog links, so nothing else needs to be installed. Guidedog's own docs/gds is one such catalog: we run guidedog dsc check in that folder. See Keep a discussion catalog.

gd-graphdog is the library that encapsulates Graphviz. Guidedog uses it to render documentation diagrams in process; it is not a separate CLI.

Publish static sites

guidedog ssg manages articles, research logs, collections, feeds, pinned theme archives, and multi-project websites from the same conf.toml and document tree:

guidedog ssg init site --preset=journal --title="Field Notes"
guidedog ssg new posts/2026-04-17-zero-copy.rst --title="Zero-Copy Readers"
guidedog ssg schedule posts/2026-04-17-zero-copy.rst --at=2026-05-01T09:00:00Z
guidedog ssg publish posts/2026-04-17-zero-copy.rst
guidedog ssg build site

Pages marked with :pdf: article also build standalone print-quality PDFs alongside their HTML pages. Multi-project websites mount sub-projects (such as docs/site, docs/manual, and docs/gds) declaratively through [[site.mounts]]; docs/api builds as a standalone reference project and manual PDF appendix. See Static site publishing.

Read and embed

  • Manual: tutorials, topics, practical tasks, reference, and internals.
  • API reference: generated from the Rust sources by Guidedog itself and included in the manual's PDF appendix. cargo doc --workspace --no-deps builds the rustdoc pages too.
  • Engine guide: workspaces, requests, adapters, and passes; examples are small programs we can run with cargo run.
  • Templates: customize HTML with Jinja and books with Typst.
  • GDS: numbered design records and implementation decisions.
  • Discussion library: the catalogs that guidedog dsc keeps.
  • Plugin library: typed build services and the publisher interface used by guidedog publish and the linked Pages plugin.
  • Reusable crates: the engine, libraries, API generators, and plugin SDK structured for independent use (built from this workspace today, with crate names reserved for crates.io), and how they depend on each other.

Each crate under crates/ has a short README with its API and its design decisions. Guidedoc owns its document tables and reuses them between conversions, so a conversion in steady state allocates nothing. It returns structured diagnostics with a hint. The host manages files, budgets, caching, publication, and the embedded compilers. --untrusted restricts capabilities; it is not a process sandbox or a limit on all native resource use. The beta scope is trusted documentation projects on Linux, macOS and Windows.
